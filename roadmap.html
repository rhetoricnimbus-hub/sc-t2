The people on it

Mamatha and Sienna are setting up P0.

The proposal end is running. Everything after it — kickoff, inputs, scheduling, monitoring, closure — is the P0 block, and none of it can be automated until the studio's current way of doing it exists somewhere other than in people's heads. That is what they are assembling now.

Mamatha

Client-side flow

Assisting now

P0 · Kickoff

Assembling the intro mail and the client input checklist that goes out with it, per project type.

P0 · Inputs

Recording how client inputs arrive today, so received items can be ticked off and pending ones chased automatically.

P0 · Approvals

Logging how approvals and revisions actually come in, so none can be lost once tracking is switched on.

Moving on to

P0 · Updates

Setting the phase-wise update format, so weekly client progress mails can write themselves.

P0 · Closure

Defining clean completion — final files, completion mail, feedback, archive — as a repeatable sequence.

Sienna

Internal delivery

Assisting now

P0 · Kickoff

Mapping the ClickUp delivery template, so every project starts the same way instead of from memory.

P0 · Tasks

Listing which department owns which task type, so allocation can be created and assigned without a meeting.

P0 · Schedule

Collecting real durations against scope items, so tentative completion dates can be calculated rather than guessed.

Moving on to

P0 · Monitor

Defining overdue and stuck, so the daily check surfaces real problems and not noise.

P0 · Capacity

Working out how free time is read off the board, so deadline alerts and resource planning have something to stand on.

Each item above is one row of the P0 sheet being turned from a description into something a system can run. It comes off their list the moment it does — and P1 and P2 only become possible once P0 is holding.
